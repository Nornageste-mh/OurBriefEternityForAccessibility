# OurBriefEternityForAccessibility

本仓库是**专门针对 Steam 游戏《永恒与星辰与日常》（Our Brief Eternity，
AppID 4169820，游戏版本 1.63）** 的屏幕阅读器辅助补丁 —— 一份游戏内
**Ren'Py 脚本叠加层**（往游戏目录放若干个 `.rpy`），通过 NVDA Controller Client /
引擎同款 SAPI 朗读屏幕上的文字。

## 说明

本辅助的作用：让使用读屏软件的玩家，也能基本正常地游玩《永恒与星辰与日常》。

- 朗读**剧情文本与旁白** —— 旁白占全部台词的 **43.2%**，这部分不以对话形式出现，
  漏掉它盲人玩家会丢掉将近一半的叙事
- 朗读**选项**，并用数字键 `1`-`9` 直接选第 N 项（全作 **3 处 / 9 分支**）
- 全部界面 `imagebutton` 的键盘导航与朗读（文案覆盖率由工具核对到 **100%**）
- 引擎内建 `_accessibility` 界面（自语音 / 字体 / 高对比 / 单声道）之上**叠加**，不替代
- 重读上一句（**F5**，按下先响一声确认音）
- 冷启动时关闭引擎的「自语音」（理由见「几条踩过的坑」）；引擎内建的 `v` 键仍然可用，
  玩家若自己打开它，补丁不与之争抢 —— 只是界面播报会退回引擎那一套

游戏版本 **1.63**，引擎 **Ren'Py 8.6.0**，运行时 Python **3.12.7**。
面向**通过 Steam 购买的正式版**（AppID 4169820），只支持 **Windows**。
开发 / 发行 **土豆花制作组**（名称由项目维护者提供，本仓库未在商店页二次核实）。

**当前状态**：已经跑通并在维护者机器上试听过（他确认可用的版本是 **0.0.4** 与 **0.0.7**），
**0.0.1.2** 已通过全部机器自检、**待维护者耳测**（0.0.1.0 / 0.0.1.1 同样是待测版，
其中 **0.0.1.1 有回归**：播报被去重判据吞掉，导航整片不朗读 —— 详见 `CHANGELOG.md`）。
对账细节见 [`docs/已验证版本.md`](docs/已验证版本.md) —— 那里区分「机器能验的」与
「只有耳朵能验的」，并且明确记着两者的**区别**：曾经有过「断言全过、引擎 lint 无错」
但补丁整片不发声的版本。

> **不需要「导航模式」。** 有些游戏的读屏补丁要先按一个键进入界面导航模式，
> 本补丁**不用** —— Ren'Py 引擎自带「焦点」系统（`focus.focus_list` / `Focus` 对象 /
> `change_focus()`：`focus.py:88-109`、`:534-579`），补丁是**挂钩**它而不是另搭一套，
> 所以方向键、回车、`Esc` 全都保持引擎原生行为，按键就是按键。
>
> 曾经写过一版导航模式（`07_uinav.rpy`），**已被维护者判为「无效，甚至更加卡手了」并删除**。
> **不要「为了和上游一致」把它加回来** —— 上游那三作需要它，是因为 Unity 的 UI
> 没有引擎级焦点系统；Ren'Py 有，再加一层模式只会把「引擎原生行为」挡在外面。
> 完整对照表见 [`无障碍可行性验证.md`](无障碍可行性验证.md) §4.4。

**朗读策略（四条规则）**：

| 情况 | 念什么 |
|---|---|
| 没有角色名（旁白 / 主角独白，占 **43.2%**） | **全文朗读** |
| 有角色名、但该角色**本来就没有配音**（主角、同事A/B/C、服务员、人事主管） | **全文朗读**（含角色名） |
| 有角色名、**有配音** + 配音听得见 | **不念** —— 配音本身就在说明是谁在说；按 **F5** 能把这一句**整句**念回来 |
| 有角色名、有配音 + 玩家把配音调成了**静音** | **全文朗读**（否则那几句会凭空消失） |

几条依据（都不是猜的）：

- 「这个角色有没有配音」按**作品事实**判定，由逐作层从游戏自己的角色定义推导：
  `scripts/roles/role.rpy` 里**有配音的角色都带 `voice_tag`**，没有 tag 就没有配音文件
  （引擎用 `config.auto_voice = "audio/voice/{id}.ogg"` 拼文件名）。
  **不硬编码任何角色名**；而且**必须按完整名精确匹配** —— 合说角色「林小凑&星弥」
  带 `voice_tag`，按子串判会在配音之上再念一遍正文。
- 「配音听得见吗」用玩家偏好里的**混音器音量**（`preferences.get_volume`），
  不用通道当前状态 —— 本作 `voice_sustain = True`，上一句的配音会留在通道里，
  拿通道状态当判据会把主角的台词误判成有配音（上一版就这么吞掉了主角的正文）。
  取不到音量时**假定听得见**（宁可少念，不可与配音打架）。
- 说话人未知时（画面上的 `？？？`）读作「未知」。
- 有配音的行**整句进重读缓冲区**，并且**打断**上一句还没念完的朗读 ——
  前者是这一句**唯一的朗读通路**，后者避免长旁白盖住配音的开头。

**永不静默**：万一某个控件没有登记文案，补丁宁可念出一个可核查的标识
（形如「未命名控件（某图.png，某动作）」），也不保持沉默 —— 沉默是最难查的故障。
**这不是故障噪音，它是探针**：把听到的那一串交给维护者，正好就是补全文案所需的信息
（它已经报出过一个覆盖率工具扫不到的控件）。

**玩家说明书在 [`mod/package/`](mod/package/) 里**（随发布包分发、可独立阅读）：
[`安装说明.md`](mod/package/安装说明.md) 讲安装 / 卸载 / 按键 / 朗读行为，
遇到问题先翻 [`常见问题.md`](mod/package/常见问题.md)。

## 安装（仅限正版玩家）

**发布包是「解压即用」的，没有安装器** —— 不需要运行任何脚本。主路径：

1. 从 [Releases](../../releases) 下载 `OurBriefEternityA11y-<版本>.zip`。
2. 找到**游戏根目录**：Steam 库里右键游戏 → 管理 → 浏览本地文件，打开的就是它
   （那一层里同时有 `OurBriefEternity.exe` 与 `game\` 子目录）。
3. 把 zip **解压到游戏根目录**，系统问「是否合并 / 替换同名文件」时选**合并 / 覆盖**。
4. 从 **Steam** 启动游戏。

zip 内的目录结构与游戏目录**一一对应** —— 这正是「解压即用」能成立的原因：

```
安装说明.md / 常见问题.md         →  <游戏目录>\                    （纯文档，可留可删）
licenses\*                        →  <游戏目录>\licenses\
game\a11y_platform\*.rpy   （6 个）→  <游戏目录>\game\a11y_platform\
game\a11y_game\*.rpy       （5 个）→  <游戏目录>\game\a11y_game\
game\nvdaControllerClient64.dll   →  <游戏目录>\game\
```

包内一共 **16 个条目**：11 个补丁 `.rpy` + 1 个第三方 DLL + 2 份玩家文档 + 2 份许可证文本
（完整条目清单与 SHA256 由 `tools\make_release.ps1` 打印）。**包里没有安装器**，
也没有任何 `.ps1`：`make_release.ps1` 的白名单（`$ALLOWED_EXT`）里没有这个扩展名，
硬塞一个脚本进去会让打包**直接报错退出**，所以这条不是靠人记得。

**装之前先关掉游戏**（引擎只在启动时读这些 `.rpy`）。

三条容易踩的坑：

- **必须从 Steam 启动游戏** —— 直接双击游戏目录里的 `OurBriefEternity.py` 会撞上
  游戏自己的报错，那不是补丁的问题
- **游戏路径含中文没关系** —— Steam 默认的 `…\steamapps\common\永恒与星辰与日常`
  就是中文目录名，本补丁实测可用（与上游 Unity 那几作「路径不能含非 ASCII」的坑**正好相反**）
- **装了但没反应时，先看版本号**：补丁版本写在开屏播报与 `log.txt` 第一行里 ——
  它能一眼分出「没装上」和「装上了但某处不对」

**怎么确认装上了**：从 Steam 启动游戏，进主菜单后应当听到这一句（版本号随构建变化，
下面这句是 **0.0.0.9** 的样子）：

> 「永恒与星辰与日常无障碍补丁 0.0.0.9 已加载。朗读后端：NVDA。」
**卸载**：删掉这两个目录就是卸载（效果与从未装过完全一样）：

```
<游戏目录>\game\a11y_platform\
<游戏目录>\game\a11y_game\
```

游戏原有文件一个都没被改过，所以删完就是原样。补丁**不生成、不修改存档，也不碰成就**。
几件小事说明一下：

- 补丁放进 `<游戏目录>\game\` 的 `nvdaControllerClient64.dll` 可以一起删；
  根目录的 `安装说明.md`、`常见问题.md` 与 `licenses\` 是纯文本，留着不影响运行。
  （本作游戏目录里本来就带同名 DLL；补丁运行时按 `<game>\a11y_platform\` → 游戏根目录
  → `<game>\` 的顺序找它，实际加载了哪一个会写进日志。）如果你的游戏目录里原本就有
  这个文件，用 Steam 的「属性 → 已安装文件 → 验证游戏文件的完整性」即可还原。
- 唯一会留在玩家偏好里的痕迹：补丁会**关闭引擎的「自语音」开关**。你随时可以在游戏
  设置里自己打开，补丁不与你争抢 —— 只是界面播报会退回引擎那一套。

**升级注意**（之前装过旧版的话）：覆盖之前先删掉 `<游戏目录>\game\a11y_platform\` 与
`<游戏目录>\game\a11y_game\` 下遗留的 `*.rpyc` —— **旧编译产物不清会影响加载**
（表现是「装了新版本但行为没变」）；或者干脆先把这两个目录整个删掉，
再把新 zip 解压到游戏目录。

## 主要快捷键

| 快捷键 | 功能 |
| --- | --- |
| `F5` | 重读上一句（按下先响一声短提示音，再朗读） |
| `F9` | 切换朗读后端：自动 → NVDA → 引擎同款 SAPI → 两者同时 |
| `1` - `9` | 选项界面：直接选第 N 项（主键盘与小键盘都认） |
| `↑` `↓` | 在控件间**线性**移动（一个不漏地走遍当前界面） |
| `回车` / `空格` | 确认当前控件（引擎原生行为） |
| `Esc` | 返回 / 关闭（引擎原生行为） |
| `Ctrl+Shift+I` | 现场快照（把当前界面识别不出的控件写进 `log.txt`，排查用） |

几点说明：

- **重读键不是 `Backspace`。** 本作把 `Backspace` 留给了文本输入，上游纪律是
  「不抢游戏原生占用的键」，所以补丁用的是 **F5**。
- **`←` / `→` 补丁不接管** —— 它们本来就是滑杆调节与视口滚动用的（引擎原生行为），
  补丁只接管上下方向键。
- **方向键为什么要接管**：引擎在自语音关闭时用**几何就近**找下一个控件
  （`focus_nearest`，要求目标严格在某个方向 + 按距离打分），在两列混排的设置界面里
  会**够不到一部分控件**（维护者原话「除了对键盘导航做出了限制就没区别了」）。
  补丁改成**按画面顺序 `(y, x)` 线性移动**：候选判据照抄引擎的 `focus_ordered`
  （`focus.py:848-866`），但**保留视口**（历史记录要靠它滚动）。
- **`F5` 那一声提示音是刻意加的**：盲人玩家分不出「键没送到」和「送到了但读屏没出声」，
  两者听感完全一样。有提示音 + 有朗读 = 正常；有提示音 + 没朗读 = 朗读通路的问题；
  没提示音 = 键根本没送到。有了它，反馈一次就能说清。
- **F9 钉死的档位不会自动回退**（这是刻意的 —— 否则你分不清「这路坏了」还是「切过去了」）；
  切到某档一片安静就说明那一路在本机不可用，再按 F9 换下一档即可。
- **不要用 `v` 键**：那是引擎内建的自语音开关，在 Windows 上走 SAPI、不认识 NVDA；
  补丁的朗读**默认已经开着**，不需要你去按它。
- 补丁的按键走 Ren'Py 的 `keymap` 机制（不自己监听原始按键），好处是玩家能在引擎设置里
  看到并修改；代价是处理函数**收不到事件**（踩过的坑第 5 条）。
- **不需要「导航模式」**，理由见「说明」里的那一段。

## 已知问题 / 注意事项


- **立绘页的缩放 / 拖动仍只有鼠标**。
- **画廊的 CG 缩略图只报「第 N 张」** —— 那些图在画面上一个字都没有，
  既没有可读标题、也不能从文件名猜内容，补丁**不编造**。
- **部分动态生成的控件不在覆盖率工具的扫描范围内**（如历史记录里每条右侧的
  「跳回这一句」「重听语音」—— 它们是 `VirtualViewport.rpy:565` 用 Python 动态建的
  `ImageButton`，screen 语句扫不到）。这些位置靠「永不静默」那条探针兜底：
  日志里报出 `图片@x,y`，就是下一轮要补的文案，而「坐标 + 图名」能直接在源码里
  查到对应的那一行控件。
- **立绘页的「当前值」播报目前是死的**：查表次序是「图片表 → 位置表 → 钩子」，
  而图片表里已经有「上一个 / 下一个」那两条，于是「组名 + 方向 + 当前值」那一段
  永远不会被调用。接通只需删掉图片表里那两条、由逐作钩子接管 ——
  那是**改进**（念「上一个，当前 星海」而不是「上一个」），不是故障，
  所以留到实机试听一并决定（见 `CHANGELOG.md` 0.0.0.6 的「已知缺口」）。
- **不支持争渡（ZDSR）读屏**，也不计划支持：本机实测 `InitTTS` 返回 0
  而判据 `GetSpeakState` 返回 2（读屏没有运行或没有授权），判据不成立。
  上游把这一级列为实验阶段，本补丁不声称支持它。


- **NVDA 控制器「只有第一条出声」**：返回码恒为 0，却只有第一句出声；同一现象在
  纯宿主脚本里**复现不出来**（`tools/probe_nvda_race.py` 连续 3×3 次正常）。
  所以**不能断言 NVDA 这条路已经可靠**。补丁为此做了 **F9**：切到「两者同时」即可
  继续用，也方便当场分辨是哪一路在响。
- **配音覆盖率算不出精确数字**：配音 id 由引擎在运行时用
  `renpy.game.context().translate_identifier` 推导（`00voice.rpy:353-379` 实查），
  它来自**原始** `.rpyc` 里的翻译标识符，反编译重编后会变，发布版也没有随包
  `dialogue.tab`。所以补丁**不在离线阶段猜覆盖率**，而是运行时用引擎自己的判据
  （`VoiceInfo.auto_filename`）逐行判定。
- **界面文案是「看图确认」的**：全部界面的 `imagebutton` 文案都靠看图登记，
  出处写在 `a11y_game/22_uialt.rpy` 的注释里，覆盖率由工具核对到 100%；
  但**没有在每种界面组合下逐个实机听一遍**。
- **快进经过的行目前照念**：上游对这类行的处置是「只记不念」，本补丁照念
  （那些行也进了缓冲区，覆盖要求是满足的），差别只在快进时读屏会不会一路念下去。
  这一条**只有耳朵能判断**，所以没动（见 `CHANGELOG.md` 0.0.0.9 的
  「待维护者定夺的对齐项」）。
- 这两类事实的**唯一权威清单**是 [`无障碍可行性验证.md`](无障碍可行性验证.md) §7.5
  与 [`docs/已验证版本.md`](docs/已验证版本.md) 的「未解决项」——改代码前请先读它们。


- 补丁靠引擎的运行时信息工作，**游戏或引擎更新后可能失效**（补丁点按引擎源码位置
  与屏幕坐标挂的）。升级引擎大版本后请重新跑一遍自检套餐与按键表。
- 补丁会**强制关闭**引擎自语音，并把这件事**写进玩家偏好**。代价如实记录：
  打开自语音后引擎念的是**容器文字**、它自己的状态词（本作把 `selected` 译作「选定」）
  与 preference 按钮的内建 alt（「跳过没见过的」）——**没有一条是控件名字**
  （维护者原话：「主菜单不读，设置界面有些读有些不读」）。两次改动的实机记录写在
  `10_renpy_adapter.rpy` 的 `ensure_self_voicing` 注释里，**改回去之前请先读它**。
- **自动播报只排队、不打断；只有玩家主动发起的朗读才打断**。实机教训：全都传「打断」时，
  开屏三句互相打断，主菜单那句刚起头就没了，听感是「菜单哑了」；剧情里则变成每一句
  都被下一句打断 —— 用户原话「读出来的大概率不是现在屏幕上显示的这一句」。
- `log.txt` 与 `a11y_speech.log` **可能含剧本原文**（对话朗读记录），属本机证据：
  **不入库、不外发、不随发布包分发**（[`.gitignore`](.gitignore) 与
  `tools\make_release.ps1` 两头都拦着）。

## 构建

补丁**没有编译步骤** —— `.rpy` 是源码，由引擎在游戏启动时自己编译。
所以这里的「构建」指的是**组装发布包**：

```powershell
powershell -ExecutionPolicy Bypass -File tools\make_release.ps1
```

- **版本号从代码里解析**（`mod\game\a11y_game\90_plugin.rpy` 的
  `A11yHost.PatchVersion`），不手写：手写过一次（标签 `v0.0.0.5` 里写着 `0.0.0.4`），
  后果是维护者按日志对账**对不出来**。现在断言 G 管「标签 = 代码」，
  `make_release.ps1` 管「包名 = 代码」，两头都机械核对，人才不用记。
- 内置 **IP 红线自检**：对「要打进包的那份清单」过黑名单 + 白名单 + 禁止目录段，
  命中就**报错退出**（不是警告）。打包时最容易的翻车方式是「顺手把整个 `game\` 目录
  塞进去」，于是把 `.rpa` / 解包产物 / 剧本原文 / 截图 / 日志一起发了出去。
- **产出是「解压即用」的包，不带安装器**：zip 内的目录结构与游戏目录**一一对应**
  （`game\a11y_platform\*.rpy`、`game\a11y_game\*.rpy`、`game\nvdaControllerClient64.dll`，
  加包根的两份文档与 `licenses\`），玩家解压到游戏根目录、合并覆盖即可。
  条目只允许落在这三处（`game\...` / 包根 / `licenses\...`）——
  多一层目录就意味着解压后不会落到游戏目录里，而玩家只会觉得「补丁没生效」，
  所以这条也机械拦住。白名单（`$ALLOWED_EXT`）里**没有 `.ps1`** ⇒
  「包里没有安装器」是**机械保证**的，不是靠人记得别放。
- **开发期自用的 `tools\install.ps1` 仍留在仓库里**，给维护者自己用
  （自动探测游戏目录、删掉补丁自己的旧 `.rpyc`、逐字节校验 dll），
  **不进发布包** —— 玩家侧不需要它，也就不会再出现「解压出来的包里那个脚本
  找不到源目录」这类只坑玩家的故障。
- zip 条目名统一为 `/`（.NET 的 `CreateFromDirectory` 与 `Compress-Archive` 在 Windows 上
  都会写成反斜杠，跨平台解包会出怪名字），写完再**重新打开逐条核验**。
- 条目时间戳固定 ⇒ 同一份源码打两次包，**zip 逐字节相同**（可对账、可复现）。
- 输出 `dist\OurBriefEternityA11y-<版本>.zip`（`dist/` 不入库，只进 Releases）。

> ⚠ 本仓库的 `.ps1`（`tools\install.ps1`、`tools\make_release.ps1`）必须保存为
> **UTF-8 带 BOM** —— Windows PowerShell 5.1 读无 BOM 的脚本会按 GBK 解码，
> 中文注释变乱码并**直接语法错误**，安装脚本整个不执行。而 `.rpy` 的规矩**正好相反：
> 不得带 BOM**。两种文件规矩相反，提交闸门两头都查（断言 A0 与断言 J）。

### 模组做了什么

| 功能 | 本作挂载点 | 依据 |
| --- | --- | --- |
| 朗读出口（后端链） | `config.tts_function` | 引擎源码实查（`config.py:575/1677`）；`main.py:332` 的 `config.init()` 在 `main.py:488` 执行 init 块**之前**，所以 init 阶段覆盖是安全的 |
| 文本清洗 | `config.tts_substitutions` | `renpy/display/tts.py:242-248`；且 `tts.init()` 在 `main.py:581` 才编译，晚于全部 init 块 |
| 抓住当前台词 | `config.say_menu_text_filter` | `ast.py:971`（say）与 `ast.py:1787`（menu 选项）；**本作未占用**这个钩子 |
| 本行有没有配音 | `VoiceInfo.auto_filename` | `renpy/common/00voice.rpy:329-386` 实查 |
| 选项朗读 | 覆盖 `screen choice`，给 `imagebutton` 加 `alt` | `scripts/screens/screen_choice.rpy` 实查 |
| 主菜单朗读 | 覆盖 `screen main_menu`，给 6 个 `imagebutton` 加 `alt` | `scripts/screens/screen_main_menu.rpy` 实查 |
| 补丁自身按键 | `config.keymap` + `config.underlay` | ⚠ `config.underlay` 在 `00keymap.rpy` 的 **`init 1100`** 被**整体赋值**，所以补丁的登记必须在 **1200** |
| 界面控件播报 | 无挂载点：焦点变化时按「图片路径 / 屏幕坐标 / 同图序号」查文案表 | 拉模型（不是往 `style.alt` 里注入），依据见踩过的坑第 9 条 |
| 方向键线性导航 | 补丁驱动焦点，最终仍调引擎的 `change_focus()` | 候选判据照抄 `focus_ordered`，但保留视口 |
| 自语音开关（冷启动） | `preferences.self_voicing` | `renpy/preferences.py:274`；本作**反向**使用：强制关闭它（见「其它注意事项」） |

**判定「本行有没有配音」的方式**：`VoiceInfo.auto_filename` 是否给出文件名；
**判定「说话人本来有没有配音」**：游戏自己的 `role.rpy` 里该角色有没有 `voice_tag`
（见「说明」的朗读策略）。

**补丁额外覆盖引擎做不到的三块**：

1. **值变化**：焦点没动、值变了（拉滑杆、切开关）引擎不会重念；
2. **滑杆**：`Bar._tts_all` 尾巴上硬编码一个「栏」字，补丁改不掉，
   于是滑杆不由引擎念、由补丁念（「音乐音量 60%」）；
3. **线性导航**：见「主要快捷键」。

### 几条踩过的坑（改之前请先读）

1. **挂载点存在 ≠ 会被调用。** `config.all_character_callbacks` 是引擎为说话人提供的
   官方接口，本作 `screen_say.rpy` 自己也在用它缓存侧边图 —— 看起来是首选，
   但**实测在本作的真实 `say` 语句上从不被触发**（探针确认「注册成功（列表里在）」
   「手动调用成功」，推进剧情时一次都没有）。⇒ 最终采用 `config.say_menu_text_filter`。
   上游铁律是「不许猜方法名和对象名」，这里补上下半句：**也不许假设一个存在的挂载点
   一定会被调用 —— 必须用日志证明它真的被调用过。**
2. **过滤器里的「说话人」是上一行的（时序陷阱）。** `say_menu_text_filter` 的执行点
   **早于** `renpy.store._last_say_who` 的赋值（`ast.py:971` vs `ast.py:985`），
   在过滤器里读它拿到的是**上一行**的说话人，实测症状是念出**角色变量名**
   （形如 `xx_：`）而不是画面上的显示名。⇒ 改成「过滤器只捕获文本 + 打标记，
   下一帧再读说话人」。
3. **`config` 字段的赋值时机必须先确认。** `config.underlay` 在 `00keymap.rpy` 的
   `init 1100` 被**整体赋值**（不是 append），按键登记因此必须在 **1200**；
   `config.tts_function` 则要在 `main.py:332` 的 `config.init()` 之前覆盖。
4. **删掉定义、留着引用 ⇒ init 链中断 ⇒ 按键层与播报层全都没跑**，
   而 `exit code = 0`、也没有 `errors.txt`（Ren'Py 的 lint 把异常写进日志却仍以 0 退出）。
   **「没报错」不等于「跑起来了」** —— 这就是 `tools\check_boot.py` 存在的理由
   （查「该出现的行在不在」）。同一类事故还教育出两条机械拦截：
   **断言 I**（`A11yHost` 的每个被引用属性必须有定义或赋值）与
   **断言 H**（`install.ps1` 的文件清单必须覆盖全部 `.rpy` —— 清单漂了 ⇒ 旧 `.rpyc`
   不被清掉 ⇒ **改了源码没反应**，本项目为此卡过好几轮）。
5. **`renpy.Keymap` 的值是「无参调用」的**（`behavior.py:550-565` → `:384-411`：
   `run(action)` 里 `action()` 没有参数）。补丁第一版把处理函数写成
   `def on_key(self, *args, **kwargs)` 并去读 `ev` —— `ev` 恒为 `None`，
   函数第一行就早退，于是 **F5 连续几个版本「装了但永远不响」**。
   **被调用就等于按键成立**：`map_event` 用 `compile_event` 拼出来的判据已经把
   「KEYDOWN / 非长按重复 / 没有按住修饰键 / 键码相符」全判完了。
   现在有**断言 E** 机械拦「键处理对象带参数」。
6. **常数必须从引擎那儿读来，不是背下来的。** 补丁曾写
   `import pygame as _a11y_pygame`（Ren'Py 8 里**没有** `pygame` 这个模块），
   于是 `ev.type != KEYDOWN` 这句守卫**恒为真** —— 真实事件类型是
   `renpy.pygame.KEYDOWN == 768`（探针实测），不是记忆里的 `2`。
7. **键名过滤器不能用「名字在 `dir(pygame.constants)` 里」当判据。**
   Ren'Py 的键名是**可组合**的（`ctrl_shift_K_r` / `alt_K_RETURN` / `repeat_K_PAGEUP`），
   那样会把合法名字当成坏名字丢掉，而 `renpy.Keymap` 照样被构造 ——
   那个键**静默变成「永不匹配」**，日志里只有一行
   `已丢弃引擎不认识的键名: ctrl_shift_K_r`。⇒ 现在用**引擎自己的 `compile_event`
   试解析**（临时把 `config.developer` 置真，让非法名字当场抛异常）。
8. **别挂 `interact_callbacks` 去做持续观察。** 它**一次交互只跑一次**
   （`core.py:2445-2446`）；主菜单逐项播报要挂 `config.periodic_callbacks`
   （每 50 ms），因为 `change_focus()` 走方向键时**不调用** `restart_interaction`
   （`focus.py:534-579`）。第一版挂在 `interact_callbacks` 上，只在「刚进主菜单、
   还没渲染、还没有焦点」那一瞬间看过一眼，此后**永不再被调用**。
9. **不要让「写入」和「读取」之间隔着一个你看不见的中间人。** 早期实现是
   「运行期把文案注入 `style.alt`」（推模型），实测**那个中间人从头到尾没起作用**：
   引擎读到空、补丁自己也读到空 ⇒ **主菜单整片哑掉**。现在是**拉模型** ——
   焦点变化时拿控件身份去逐作层文案表里查。而且**注入判据与播报判据必须是同一条**，
   否则会出现「注入器以为它有文本、播报却读到空」的死角。
10. **「空」有两种含义，必须分开。** `SayBehavior._tts_all` **无条件**
    `raise TTSRoot()`（`behavior.py:716`），那是引擎在明确说「别念我」。
    把这种「空」当成「我不认识这个控件」走兜底，结果是**每句台词都被
    「未知控件（SayBehavior）」顶掉** —— 而每句台词都会新建一个 `SayBehavior`，
    所以是每句都中招。
11. **坐标只用来定先后，不用来算位置。** 早期按「算出来的坐标与实际相差 ≤2 像素」
    校验，而存读档格子按钮是 462×260、格子（frame）是 462×306（左上角差 46 像素），
    于是**12 个存档位一个都不出声**，日志里只有一行「未识别」——
    看起来像**还没做**，不像**做错了**。现在同图控件按 `(y, x)` 排名次
    （`ctx.ordinal`），内边距、尺寸、对齐怎么变都不影响。
12. **有配音 / 快进经过的行也必须进重读缓冲区**（上游硬规则，本仓库到 0.0.0.9 才对齐）。
    只 `stop()` 而不记缓冲区，玩家按重读会念出**上一句**，听起来像「这一句翻不回来」。
    有配音的行要记**整句**，并且要**打断**上一句还没念完的朗读，
    否则长旁白会盖住配音的开头。
13. **`init python in <名字>:` 创建的是独立命名空间 store** —— 那个名字**不会**成为
    默认 store 的属性，块内也引用不到自己 ⇒ 在别的 init 块里写 `a11y_rpy.foo()`
    是 `NameError`，**中断整个 init**（连后端链都起不来）。本补丁统一成
    「单一默认 store + `A11y` 前缀」，跨文件引用走 `A11yHost` 上的具名槽位。
14. **不要用 PowerShell 文本 cmdlet 改 `.rpy` 或 `.ps1`。**
    `Get-Content | Set-Content -Encoding UTF8` 会把 `.rpy` 变成**带 BOM 的乱码**
    （断言 A0 专拦，而当时坏文件还被装进了游戏目录）；`.ps1` 的规矩**正好相反、
    必须带 BOM**（断言 J 专拦）。两种文件规矩相反，别记混。
15. **不要「为了和上游一致」给这个补丁加导航模式** —— 理由见「说明」的最后一段。
    上游需要它是因为引擎没有焦点系统；Ren'Py 有，加一层模式只会把
    「引擎原生行为」挡在外面，那正是「更加卡手」的来源。
16. **不要用「控件对象身份」当去重键。** 引擎每轮 interaction 都会**重建** screen 里的
    displayable，所以 `id(w)` 只在**同一轮**里稳定；本作音声播放界面带一个
    每 0.1 秒重启 interaction 的 timer（`music.rpy:336-338`），于是同一个按钮
    每 0.1 秒换一个对象 —— 「同 id 才算同一个控件」的去重**永远不成立**，
    而重读层 1.0 秒的去重窗口一到期就再念一遍。实机听感正是维护者报的
    「按方向键朗读抽搐」（日志里同一句话**精确地约 1 秒一次**）。
    现在去重键是**（文本 + 界面名 + 坐标）**，与对象身份无关；
    「同一个控件文本变了」那条支路（滑杆 / 立绘当前值）也同样改用位置键。
17. **筛子只筛一层 = 假修复。** 引擎把状态词 `selected` 追加在
    `Button._tts_all` 的返回值上（`behavior.py:1202-1203`），而补丁的文本解析是
    「① `style.alt` → ② `_tts_all` → ③ 查表」四级。只在 ① 筛掉状态词，
    ② 会把它**原样交回来**，③ 永远走不到 ⇒ 曲目名念成 `selected`。
    **判据要覆盖整条链，不是覆盖第一级**；筛空之后要继续往下走，不能 `return`。
    现在有 `tools/probe_state_word.py` 钉住它（含「旧写法是假修复」的回归断言）。
18. **「查不到」与「值就是 None」必须有不同返回值。** 0.0.1.1 把这两件事都写成
    `(None, None)`，于是所有查不到位置的控件**共用一个去重键** ⇒ 第一个念过之后
    其余全被吞掉，实机表现是**导航整片不朗读**（焦点行在日志里刷，
    `[alt] 播报:` 一行都没有）。位置改三级取法、**不依赖缓存的那一级排最前**
    （现读引擎 `focus_list`），查不到时返回**哨兵**而不是 `(None, None)`。
    `tools/probe_focus_key.py` 钉住它。**宁可吵，不可哑。**
19. **改「去重 / 让位」类判据，必须同时验两个方向。** 0.0.1.1 只验了
    「不该重复的还重不重复」（按日志看重复确实没了），**没验「该念的还念不念」**
    ⇒ 把「去重过头 = 全哑」当成了修好。同类判据（去重窗口、打断降级、
    让位规则）都要**双向**验证：一次「还念得出来」+ 一次「没有多念」。

## 如何复现分析

分析过程依赖若干 Python 脚本（`tools/README.md` 里有逐条说明）：

```powershell
$py = "<任意 Python 3.8+>"

# 1) RPA 解包（只读地列 / 取 .rpa 内容；产物不入库）
& $py tools\rpa.py "<游戏目录>\game\scripts.rpa" -o extracted\scripts

# 2) 反编译 .rpyc -> .rpy（unrpyc，见下面的致谢；工具本身也不入库）
git clone --depth 1 https://github.com/CensoredUsername/unrpyc.git tools\unrpyc
& $py tools\unrpyc\unrpyc.py -c -p 8 extracted\scripts

# 3) 离线 API 核查（用游戏自带的运行时 Python，不启动游戏）
& "<游戏目录>\lib\py3-windows-x86_64\python.exe" tools\probe_api.py

# 4) 后端实证（不依赖游戏）
& $py tools\probe_dll.py        # 读 PE 导出表，核对要用的符号名（不许猜）
& $py tools\probe_backend.py    # 实测 NVDA / SAPI 能不能用、vtable 槽位对不对

# 5) 离线按键探针（用引擎自己的 compile_event / map_event / Keymap）
& "<游戏目录>\lib\py3-windows-x86_64\python.exe" tools\probe_keymap.py

# 6) 实机取证
powershell -ExecutionPolicy Bypass -File tools\install.ps1
# 把 mod\game\a11y_game\90_plugin.rpy 的 CfgDiagLog 改为 True 后启动游戏，
# 复现问题后按 Ctrl+Shift+I 打一份现场快照
& $py tools\read_log.py         # 只看 [A11y] 行（含剧本原文，**不得提交 / 外传**）
```

> ⚠ `import renpy.config` 直接写在脚本开头会失败（`config.py` 在模块级引用
> `renpy.error.TracebackException`）—— `probe_api.py` 里是**复用引擎自己的导入清单
> 反复迭代到稳定**的，不是手写子集。
>
> ⚠ **`CfgDiagLog=True` 期间的 `log.txt` 含剧本原文**，按 IP 红线**不得入库、
> 不得外传**，只在本机排查时临时开。

**自检套餐**（发布前跑一遍 —— 这六条合起来就是本项目的「机器验证」）：

```powershell
python tools\lint_patch.py        # 12 条静态断言：A0 编码 / A 语法 / A2 顶层 / B 隔离
                                  #   / C 出口 / D 键名 / E 无参 / F 接线 / G 版本号=标签
                                  #   / H 安装清单 / I 契约属性 / J .ps1 的 BOM
python tools\coverage_uialt.py    # 控件文案覆盖率（应 100%）
python tools\probe_ordinal.py     # 序号逻辑（第几个存档位）离线单元测试
python tools\probe_state_word.py  # 状态词筛子（裸 selected 必须判空，名字不能被砍）
python tools\probe_focus_key.py   # 去重键（「查不到位置」不得退化成共用一个键 ⇒ 静默）
python tools\probe_speech.py      # 朗读后端调度离线单元测试（含「说错话」回归点）
python tools\check_game_names.py  # 补丁引用的游戏侧名字是否真的存在
python tools\check_boot.py        # ★ 启动证据：查「该出现的行在不在」，不只看「有没有报错」
```

**这些各自防住一类会静默失效的错误**，都不是形式主义 ——
每条断言都对应一次**真实发生过**的事故，来历写在
[`无障碍可行性验证.md`](无障碍可行性验证.md) §8.4、
[`CHANGELOG.md`](CHANGELOG.md) 与 [`tools/README.md`](tools/README.md) 里：

- **断言 E** —— 键处理函数带参数 ⇒ 那个键**永远不响**（F5 那次）；
- **断言 G** —— 版本号与标签不符 ⇒ 日志没法对账（整理版自称旧版本号那次）；
- **断言 H** —— 安装清单漂了 ⇒ 旧 `.rpyc` 不被清掉 ⇒ 「改了源码没反应」；
- **`check_boot.py`** —— 删常量漏了引用 ⇒ init 链中断 ⇒ 按键与播报两层全没跑，
  而 `exit code = 0`、无 `errors.txt`；
- **覆盖率** —— 漏一个控件，表现只是「安静」，没有任何别的痕迹；
- **序号探针** —— 序号算错会**报错位号**（听着「存档位 3」却覆盖了第 5 位），后果最重；
- **状态词探针** —— ★ **筛子只筛一层等于没筛**。只筛 `style.alt` 时，
  引擎会在下一级（`_tts_all`）把状态词原样交回来，查表那一级永远走不到；
  实机症状是曲目名的位置一直念 `selected`。探针里专门留了一条**假修复回归**；
- **去重键探针** —— ★ **「查不到」与「值就是 None」必须是两个返回值**。
  混用会让所有查不到位置的控件共用一个去重键 ⇒ 第一个念过之后其余全被吞掉，
  实机症状是**导航整片不朗读**而日志里焦点行照刷（0.0.1.1 的真实事故）；
- **朗读探针** —— ★ **查询接口与执行接口对同一份状态的解读必须一致**。实机事故：
  开屏播报说「没有可用的朗读后端」，而那句话**正是被读屏念出来的** ——
  这种不对称只在「先查询、后执行」的顺序下暴露，而且暴露方式是**说出自相矛盾的话**，
  最容易被误判成「读屏坏了」；
- **名字核对** —— 游戏侧名字写错时，`try/except` 会把它变成「没有文案」，
  看不出是错的。

最后是**只有耳朵能验的那一半**：上面这套工具验的是**机器能验的**，
「键按下去到底响了没有、念得对不对」只能实机听。逐条清单在
[`测试问卷.md`](测试问卷.md) —— 一条一个勾选框 + 一栏「听到了什么 / 没听到」，
由维护者（读屏用户）自己勾。**两者不能互相替代**：本项目出现过
「断言全过、引擎 lint 无错」但补丁整片不发声的版本。
