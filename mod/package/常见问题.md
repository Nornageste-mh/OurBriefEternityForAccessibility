# 常见问题

> 《永恒与星辰与日常》读屏无障碍补丁 · 发布包内文档。
> 安装 / 卸载 / 按键表 / 朗读行为见同目录的 [`安装说明.md`](安装说明.md)。

每条都对应**真实发生过**的情况。排查顺序建议从第 1 条往下走 ——
它能把问题一刀切成「没装上」和「装上了但某处不对」。

---

## 1. 装了补丁，但从头到尾一声不响

**先做一件事**：从 Steam 启动游戏，进主菜单，听有没有这一句 ——

> 「永恒与星辰与日常无障碍补丁 X.Y.Z.W 已加载。朗读后端：NVDA。」

* **听到了** ⇒ 补丁在跑，问题在后面某一条（继续往下看）。
* **没听到** ⇒ 补丁没跑起来。依次检查：
  1. 游戏目录下是否真有 `game\a11y_platform\` 与 `game\a11y_game\` 两个目录；
  2. 是不是从 **Steam** 启动的（直接双击游戏目录里的 `.py` 会撞上游戏自己的
     `quit_once` 报错，那不是补丁的问题）；
- 玩家侧**不需要跑任何脚本**：把游戏目录下的 `log.txt` 与 `a11y_speech.log` 发给维护者即可（见下）。
     ⚠ **"没有报错"不等于"跑起来了"**：曾经有个版本删了一个常量的定义却漏了引用，
     init 链中断、按键层与播报层全都没执行，而引擎仍然以 `exit code 0` 退出。

## 2. 只有第一句能听到，之后全静默

这是 NVDA 控制器那条路上的**已知未解决的问题**（上游在纯宿主脚本里复现不出来，
所以补丁不假装它不存在）。补丁为此专门做了 **F9**：

| 按 F9 切到 | 用的路 |
|---|---|
| 自动（默认） | NVDA 控制器 → 失败时退回 say.vbs |
| NVDA | 只用 NVDA 控制器 |
| 引擎同款 SAPI | 用游戏自带的 `say.vbs`（历史上最稳的一条路） |
| 两者同时 | 同时走两条，用来分辨到底是哪一路在响 |

「两者同时」按下去会听到两遍 —— 那是**故意**的，它就是给排查用的。

## 3. 主菜单不读，但剧情能读

**先确认版本号**（补丁版本写在开屏播报和 `log.txt` 第一行里）。
0.0.0.5 之前的版本有过这个故障，原因是补丁自己的两条判据不一致：
判断「要不要给这个控件补文案」和判断「播报时能读到什么」用的不是同一把尺子，
于是主菜单的按钮**两头都以为对方管了**，结果整片哑掉。

如果版本已是 0.0.0.5 或更高，请把 `log.txt` 发给维护者，并留意里面这两行：

```
[alt] 焦点=ImageButton 文本='开始游戏' 引擎队列=0
[alt] 播报: 开始游戏
```

第一行说明焦点落在什么控件上、补丁把它读成了什么；
第二行说明补丁确实念了。**两行都有却没声音** ⇒ 问题在朗读后端（见第 2 条）。

## 4. 设置界面有些读、有些不读

同样是 0.0.0.5 之前的问题，而且原因很有意思：那时候补丁把界面播报
交给引擎（打开引擎的「自语音」），而引擎念出来的是**它自己凑的文本** ——
设置界面里的一段说明文字、它自己的状态词（「选定」）、
以及它给 preference 按钮内建的英文 alt 的译文（「跳过没见过的」）。
**没有一条是控件名字。**

现在补丁**强制关闭**引擎自语音，控件播报由补丁自己查表念，
念的是控件上真正印着的字。

## 5. 剧情里反复冒出一个「未知控件」

**0.0.0.3 已修**。原因：对话时焦点落在引擎的 `SayBehavior` 上，而它
`raise TTSRoot()` —— 那是引擎在明确说「别念我」。补丁一开始把这种"空"
误当成"我不认识这个控件"，于是每句台词都被「未知控件（SayBehavior）」顶掉；
而每句台词都会新建一个这种对象，所以是每句都中招。

现在补丁会分清「空」的两种含义：**我不知道这是什么**（报标识）
和**引擎说了别念我**（保持安静）。

## 6. 方向键走不到某些控件

**0.0.0.5 已修**。引擎在自语音关闭时用「几何就近」找下一个控件
（要求目标严格在某个方向 + 按距离打分），在两列混排的设置界面里
会够不到一部分控件。现在方向键由补丁接管，**按画面顺序线性移动**，
一个不漏。

## 7. 某个控件念得不好听（比如「未命名控件（某图.png，某动作）」）

这不是故障噪音，而是**探针**：它说明这个控件的文案还没登记，
而补丁宁可念一个可核查的标识，也不保持沉默（沉默是最难查的故障）。

**把它交给维护者就够了** —— 那一串里的图片名与动作名正好是补文案所需的信息。

## 8. 怎么把日志交给维护者

游戏目录下两个文件：

```
<游戏目录>\log.txt            每次运行覆盖，含补丁的启动与播报记录
<游戏目录>\a11y_speech.log    累积追加，含每次朗读的文本与后端返回码
```

⚠ **这两个文件可能含剧本原文**（对话朗读记录），所以：
**只发给维护者排查用，不要公开贴出、不要提交进仓库**（`.gitignore` 已拦截）。

按 **Ctrl+Shift+I** 可以让补丁把「当前界面识别不出的控件」写进 `log.txt` ——
那份清单就是下一轮要补的文案，格式是 `图片@x,y`，能直接在源码里查到对应的控件。

## 9. 补丁会改动游戏吗？会影响存档和成就吗？

不会：

* 补丁只往游戏目录放自己的 `.rpy`，**游戏原有文件一个都没改**，
  也没有重新打包任何 `.rpa`；
* 不生成、不修改存档，也不碰成就；
* 卸载就是删掉 `game\a11y_platform\` 与 `game\a11y_game\` 两个目录。

唯一一个会留在玩家偏好里的副作用：补丁会**关闭引擎的「自语音」**开关
（因为打开它反而会让界面播报变成引擎凑出来的文本）。
你随时可以在游戏设置里自己打开它，补丁不与你争抢 ——
只是界面播报会退回引擎那一套。

## 10. 支持争渡（ZDSR）吗？

**不支持，也不计划支持。** 上游把争渡列为实验阶段；本机实测
`InitTTS` 返回 0 但 `GetSpeakState` 返回 2（读屏没有运行或没有授权），
判据不成立。按维护者决定，本补丁不声称支持它。

## 11. 我在某个界面卡住了 / 某个功能读不出来

请带上三样东西反馈：

1. 你**听到的**（不用准确，说个大概）；
2. `log.txt` 与 `a11y_speech.log`；
3. 是在哪个界面、按了什么键。

有了这三样，维护者能直接从日志里看出「是没送到后端」还是
「送到了但读屏没出声」—— 这两种情况在耳朵里**完全一样**，
但在日志里分得很清楚。
