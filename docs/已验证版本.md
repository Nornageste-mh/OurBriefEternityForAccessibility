### 未解决项（不许写成已修复）

- **F10「朗读整个界面」实测无预期效果**。0.0.0.6 修过一次（`tts.displayable(None)`
  在自语音为假时直接 return，改成调用期间临时打开自语音），**维护者实测仍无效**，
  说明还有别的原因没查到。按维护者要求**已从播报提示与面向玩家的文档中撤下**，
  键与代码保留待查。
- 立绘页「当前值」播报是死的（图片表先于逐作钩子命中）——属**改进**而非故障，
  接通办法见 `CHANGELOG` 0.0.0.6 的「已知缺口」。

### 0.0.0.5 的按键故障（重要）

那次整理删掉了契约层的 `CfgKeyCue` 字段，而 `key_cue()` 还在读它 ⇒ `AttributeError`：

| 键 | 后果 |
|---|---|
| **F5 重读** | 在「响提示音」那一步抛出 ⇒ **`repeat()` 永不执行** |
| **F9 后端切换 / F10 整屏朗读 / Ctrl+Shift+I** | 处理函数整段在 `try` 里，异常被吞 ⇒ 静默失灵 |

⚠ **教训**：维护者当时试听并反馈「没问题」，**但没有按过这四个键** ——
**「某个版本没问题」只覆盖试过的路径。** 每次发布前请把按键表**整个按一遍**
（F5 应该有那声提示音）。现在有断言 I 在静态层面拦这类「删了定义、留着引用」的错误。

### 版本号事故（重要，因为它影响"按日志对账"）

整理那一版（标签 `v0.0.0.5`）**忘了改 `PatchVersion`**，于是装进游戏的构建
**自称 0.0.0.4**。维护者因此按日志汇报「.4 没问题」——
而那个版本号无法区分 `.4` 与"自称 .4 的整理版"。

分辨靠的是**日志行为特征**（版本号以外的东西）：

| 特征 | .4 | .5 |
|---|---|---|
| 逐项播报行 | `[alt] 兜底播报（引擎未报这一条）:` | `[alt] 播报:` |
| 焦点行 | `[alt] 焦点=X alt='…'` | `[alt] 焦点=X 文本='…'` |
| 心跳行 | 含 `已补=N` | 不含 `已补=` |

结论：维护者测的就是 `.5` 的代码 ✓。已修正版本号、标签重新指向修正后的提交，
并**新增断言 G**（带版本标签的提交，`PatchVersion` 必须与标签一致）——
反向验证过：故意写错会当场报错。

## 0.0.0.5 与 0.0.0.4 的差别（**只有代码，没有行为**）

删除的都是**从未执行**或**已被取代**的东西：

- 推模型注入（`_inject` / `_set_alt` / `_applied` / `_has_alt` / `_has_text_child`）
  —— 它依赖的中间人 `style.alt` 从头到尾没起作用，实际播报走的是查表；
- `07_uinav.rpy`（导航模式，已被 `08_uialt.rpy` 的线性导航取代）
  与 `21_uilabels.rpy`（只为它服务）；
- 契约层的 `uinav` / `UiLabels` / `CfgForceSelfVoicing` 槽位；
- `05_repeat.rpy` 的 KEYDOWN 机制（基于「键处理函数能读到事件」这个**错误前提**）；
- `10_renpy_adapter.rpy` 里 5 个指向已删函数的跟踪字段。

注释同时收敛成「不变量 + 引擎依据（带 `文件:行号`）+ 为什么」，
长故事搬进 `CHANGELOG.md`。

**日志标签在 .5 里改了名**（若你按日志对账，注意这点）：

| .4 的写法 | .5 的写法 |
|---|---|
| `[alt] 兜底播报（引擎未报这一条）: 文本` | `[alt] 播报: 文本` |
| `[alt] 焦点=X alt='文本' 引擎队列=N` | `[alt] 焦点=X 文本='文本' 引擎队列=N` |
| `[alt] 心跳 #N: 焦点候选=N 已补=M 未识别=K` | `[alt] 心跳 #N: 焦点候选=N 未识别=K` |

（`.4` 那版的「兜底播报」这个名字本身有误导性：它念的文本大多数来自**查表**，
不是兜底。改名是为了不再误导下一个读代码的人。）

## 怎么验（机器部分）

```powershell
python tools\lint_patch.py        # A0 编码 / A 语法 / A2 顶层 / B 隔离 / C 出口 / D 键名 / E 无参 / F 接线
python tools\coverage_uialt.py    # 控件文案覆盖率（应 100%）
python tools\probe_ordinal.py     # 序号逻辑（存档位号算错会报错位号，比不报更糟）
python tools\probe_speech.py      # 朗读后端调度
python tools\check_game_names.py  # 游戏侧名字
tools\install.ps1                 # 安装
（引擎 lint 之后）
python tools\check_boot.py        # ★ 启动证据：查「该出现的行在不在」，不只看「有没有报错」
```

⚠ `check_boot.py` 是**事故的产物**：曾经有个版本删了一个常量的定义却漏了引用，
init 链中断、按键层与播报层全都没执行，而 `exit code` 是 0、也没有 `errors.txt`。
**"没报错"不等于"跑起来了"** —— 这条要看正向证据。
