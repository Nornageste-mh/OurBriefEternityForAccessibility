# tools 使用说明

分两类：**日常自检套餐**（发布前必跑）与**一次性探针**（历史上用过，需要时再跑）。
每个脚本开头都写了自己验证的是什么、以及它防住的是哪一类**静默故障**。

---

## 一、自检套餐（发布前跑一遍）

| 脚本 | 验证什么 | 防住的静默故障 |
|---|---|---|
| `lint_patch.py` | 静态断言 A0 编码 / A 语法 / A2 顶层 / B 隔离 / C 出口 / D 键名 / E 无参 / F 接线 / G 版本号=标签 / H 安装清单 / I 契约属性 / J .ps1 的 BOM | 每一类都真的发生过一次，见下表 |
| `coverage_uialt.py` | 全部界面 `imagebutton` 是否都有朗读文案 | 漏一个控件，表现只是「安静」 |
| `probe_ordinal.py` | 序号逻辑（同图控件按 (y,x) 排名次）的离线单元测试 | 序号算错会**报错位号**（听着「存档位 3」却覆盖第 5 位） |
| `probe_state_word.py` | 状态词筛子（裸 `selected` 必须判空、名字不能被砍） | 筛子只筛一层 ⇒ 引擎在下一级把状态词交回来，曲目名念成 `selected` |
| `probe_speech.py` | 朗读后端调度（含「说错话」回归点） | 后端自称「没有后端」却还在出声 |
| `check_game_names.py` | 补丁引用的游戏侧名字是否真的存在 | 游戏更新后名字变了，补丁静默失效 |
| `check_boot.py` | 启动后日志里**该出现的行**在不在 | 「没报错」不等于「跑起来了」 |

### 各条断言的来历（都不是形式主义）

| 断言 | 它防住的事故 |
|---|---|
| **A0** 不得带 BOM | 用 PowerShell 改过 `.rpy` 会带 BOM（+中文乱码），引擎直接报错 |
| **A/A2** 语法与顶层结构 | 顶层写了引擎认不出的语句，整个文件失效 |
| **B** 平台层不得出现本作专有标识符 | 复用平台层到别的作品时，本作的残留会被静默带过去 |
| **C** 逐作层不得绕过重读出口直呼后端 | 绕过出口后，F5 重读读不到它 |
| **D** 键名必须被引擎认识 | 写错键名 ⇒ 那个键**永不匹配**（`ctrl_shift_K_r` 那次） |
| **E** 键处理对象必须无参 | `renpy.Keymap` 无参调用；带参数 ⇒ 键**永不响**（F5 那次） |
| **F** 逐作层文案接线必须在 | 接线语句被删掉后，前几百行全部作废，而其余断言照样通过 |
| **G** `PatchVersion` 必须与标签一致 | 版本号与标签不符 ⇒ 日志没法对账（整理版自称旧版本号那次） |
| **H** 安装清单必须覆盖全部 `.rpy` | 清单漂了 ⇒ 旧 `.rpyc` 不被清掉 ⇒ **改了源码没反应** |
| **I** 契约属性必须有定义 | 删定义漏引用 ⇒ 异常被 `try` 吞掉 ⇒ **整段按键失效**（F5 / F9 / F10 / Ctrl+Shift+I 全哑） |
| **J** `.ps1` 必须带 BOM | 无 BOM ⇒ PowerShell 5.1 按 GBK 解码中文 ⇒ 语法错误、**安装脚本整个不执行**（症状是「装了但游戏里还是老代码」） |

### 附带

| 脚本 | 用途 |
|---|---|
| `install.ps1` | 安装 / 卸载（`-Uninstall`）/ 指定游戏目录（`-GameDir`）。**只放补丁自己的文件**。**这是开发期工具，不进发布包**（发布包是解压即用、不含安装器） |
| `make_release.ps1` | 打发布包 `dist\OurBriefEternityA11y-<版本>.zip`。版本号**从 `90_plugin.rpy` 解析**（不手写，免得与代码不一致）。内置 **IP 红线自检**（白/黑名单 + 禁止目录段 + zip 条目清单核对，命中即报错退出），条目时间戳固定 ⇒ **两次打包哈希相同** |
| `read_log.py` | 把游戏目录的 `log.txt` / `a11y_speech.log` 按 UTF-8 读出来（控制台直接看会乱码） |
| `scan_imagebuttons.py` | 扫某个界面文件，逐控件列出图片/坐标/动作（补文案时用） |
| `rpa.py` | 只读地列/取 `.rpa` 内容（**开发期工具，产物不入库**） |

## 二、一次性探针（历史，需要时再跑）

这些是排查特定问题时写的，结论都已写进 `无障碍可行性验证.md`。
留着是为了下次遇到同类问题时不必从零写。

| 脚本 | 当时查的问题 | 结论 |
|---|---|---|
| `probe_keymap.py` | 按键层到底怎么被调用、处理函数收到几个参数 | `renpy.Keymap` **无参调用**（`behavior.py:559→411`）；顺带查出 `renpy.pygame.KEYDOWN == 768`、Ren'Py 8 里没有 `pygame` 模块 |
| `probe_api.py` | 引擎各 API 是否存在、语义如何 | `config.interact_callbacks` 一次交互只跑一次；`periodic_callbacks` 每 50 ms；`tts.displayable()` 全引擎只有一个调用点 |
| `probe_backend.py` | 三个朗读后端各自能不能用 | NVDA 控制器可用；裸 COM SAPI **崩溃**（`0xC0000005`），故不注册 |
| `probe_dll.py` | NVDA 控制器 DLL 的导出与返回值 | `testIfRunning → 0`、`speakText → 0`（返回 0 不等于出声，这个坑见下） |
| `probe_nvda_race.py` | 「只有第一句出声」是否与取消朗读有关 | **未复现**，故补丁不假装已修；这是 F9 存在的理由 |
| `probe_speak_seq.py` | 连续朗读的先后与打断行为 | 用于确认 `interrupt` 策略 |
| `key_probe.ps1` | 早期用来抓按键事件（PowerShell 侧） | 已被 `probe_keymap.py` 取代 |
| `script_stats.py` / `script_stats2.py` | 统计剧本规模（旁白占比、配音行数） | 旁白占 **43.2%**，故「无配音内容全文朗读」是硬要求 |

---

## 三、注意

* 所有脚本都按 **UTF-8** 读写；提示信息在 GBK 控制台可能显示为乱码，
  这是控制台的显示问题，不影响判断（用 `read_log.py` 看日志可避免）。
* **不要用 PowerShell 的 `Get-Content`/`Set-Content` 改 `.rpy` 或 `.ps1`**：
  前者会把 `.rpy` 变成带 BOM 的乱码（断言 A0 专拦），后者相反、**必须带 BOM**。
